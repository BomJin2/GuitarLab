# 로컬 백업과 복원 미리보기

2026-10-21 기준입니다. GuitarLab의 환경 설정에서 백업 ZIP을 만들고 검사하거나, 새 폴더에 풀어 확인할 수 있습니다. 현재 사용하는 앱 데이터를 자동으로 교체하는 기능은 아직 없습니다. 구현·검증 상태는 [Phase 8 기록](progress/PHASE-08.md)을 따릅니다.

## 백업 만들기

1. 녹음 중이면 STOP을 눌러 저장을 마칩니다. 다른 파일 저장 작업도 끝냅니다.
2. 환경 설정의 ‘로컬 데이터 백업’에서 개인 녹음·메모·외부 파일 경로가 포함됨을 확인하고 동의합니다.
3. ‘새 ZIP으로 백업’을 누르고 새 파일명을 정합니다. 기존 파일은 덮어쓰지 않습니다.
4. ‘새 ZIP에 …개 파일을 보존했습니다’가 표시될 때까지 기다립니다. 중단하려면 ‘백업 취소’를 누르고 정리가 끝날 때까지 기다립니다.

프로젝트·악보·연습 기록·관리용 복사 음원·녹음과 불완전 테이크·보정값을 보존합니다. 앱에서는 최대 256MiB, ZIP 안 파일 수는 manifest를 제외하고 최대 9,999개입니다. ZIP은 암호화하지 않으며 개인 녹음과 메모가 들어 있습니다. 네트워크 업로드는 하지 않습니다.

## 기존 ZIP 검사

‘백업 ZIP 검사’에서 파일을 고릅니다. 복사하거나 압축을 풀지 않고 파일 목록·경로·크기·CRC·SHA256을 확인합니다. 생성 동의 체크 없이 검사할 수 있습니다. 지문 확인은 파일이 백업 당시 manifest와 일치한다는 뜻이며, 출처의 신뢰성이나 실제 전체 프로젝트 복원 성공을 보장하지 않습니다.

손상·지문 불일치·지원하지 않는 ZIP은 오류를 표시합니다. 파일을 수정하거나 검사 성공처럼 표시하지 않습니다.

## 새 폴더 복원 미리보기

1. 로컬 백업·새 폴더 추출 동의를 체크합니다.
2. ‘새 폴더 복원 미리보기’를 누르고 검사할 ZIP을 고릅니다.
3. 복사본을 둘 상위 폴더를 고릅니다. 그 안에 새 `GuitarLab-backup-preview` 폴더가 생깁니다. 같은 이름이 이미 있으면 다른 상위 폴더를 고릅니다.
4. 추출·데이터베이스 검사가 끝나면 해당 새 폴더에서 파일을 확인할 수 있습니다.

원본 ZIP과 기존 파일은 보존합니다. 현재 AppData와 겹치는 목적지는 거부합니다. 취소·실패 시 자신이 만든 임시 폴더만 정리하고 기존 목적지를 덮어쓰지 않습니다. 검증이 끝난 뒤 이미 게시한 복사본은 늦은 취소로 삭제하지 않습니다.

이 작업은 파일과 SQLite v8/v9의 무결성·참조 관계·비활성 녹음 상태를 확인합니다. DB의 실제 버전을 ZIP 목록에 보존하고 검사 때 SQLite 헤더 버전과 일치하는지도 확인합니다. v9에서 보관한 프로젝트의 marker와 악보·녹음도 백업에 남습니다. 앱의 현재 프로젝트 목록은 바뀌지 않으며, 새 폴더를 실제 AppData에 복사하거나 교체하는 기능은 미구현입니다. 미리보기 성공을 새 PC 복원 성공으로 간주하지 않습니다. v9 DB는 v8까지만 지원하는 구버전 앱으로 열 수 없습니다.

## 포함하지 않는 항목

- AI 모델·가중치·설치 환경과 다운로드 캐시: 새 환경에서 별도로 설치해야 합니다.
- 외부 파일을 참조하도록 저장한 음원: DB의 기존 경로만 남으며 파일 자체는 복사하지 않습니다. 완료 문구의 외부 참조 수를 확인합니다.
- 로그와 시스템·YouTube 오디오: 백업에 추가 캡처하지 않습니다.

개발용 `scripts/backup_local_data.py`는 별도 경로입니다. CLI 백업은 앱 종료 확인 후 최대 2GiB를 지원하며, 앱 UI의 256MiB 한도와 구분합니다. CLI 역시 실제 AppData 교체를 수행하지 않습니다.
