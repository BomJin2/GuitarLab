# 04. 악보 엔진 · TAB 편집 · 원곡 싱크

## 편집 적용·삭제 뒤 단축키 초점 — 2026-10-28

음표 속성을 반영하는 폼 재생성으로 눌렀던 버튼/필드가 사라지거나 비활성화돼 초점을 잃으면, 편집 영역의 초점을 스크롤 이동 없이 복원합니다. 적용/삭제·Undo/Redo 직후 Ctrl+Z/Y를 이어 사용할 수 있어야 하며 입력칸의 기본 되돌리기·편집 영역 밖 키와 파일 처리 잠금은 유지합니다. 검증 결과와 사용자 수동 확인은 PHASE-05 최신 절을 따릅니다.

## 악보 파일 출력 취소·문맥 보호 — 2026-10-28

현재 편집본은 실제 악보 문서, 저장 버전은 화면에 조회된 버전을 출력 문맥으로 사용합니다. 같은 문서로 돌아와도 이전 명령을 재사용하지 않고 문서 변경의 첫 반환부터 이전 오류·성공/진행을 숨깁니다. 처리 중 취소하거나 문서를 바꾸면 실제 파일 작업 종료까지 편집/출력을 잠그고 취소 정리 상태를 표시합니다. 일반 화면 갱신은 원본 기반 편집의 출력을 취소하지 않습니다. 이미 만든 새 파일과 원본/저장 head·Undo는 유지합니다. 결과와 실제 GUI 미실행은 PHASE-05 최신 절을 따릅니다.

## 저장 조회의 프로젝트 문맥 보호 — 2026-10-26

저장 목록/읽기 전용 미리보기는 현재 projectId에 맞는 내용만 반환합니다. 프로젝트를 바꾸거나 같은 ID로 돌아온 뒤 이전 조회/취소 함수를 다시 호출해도 새 문맥에 파일 작업/취소를 적용하지 않습니다. 이탈 후 호출도 차단하고 현재 문맥의 정상 취소/오류 시 이전 조회 보존은 유지합니다. 편집/Undo·저장 head/원본·플레이어는 변경하지 않습니다. 실제 검사/미실행은 PHASE-05 최신절을 따릅니다.

## 원본 기반 저장 TAB 확장 — 2026-10-26

아래 정규화 한정 후속을 확장해 renderSource가 없는 버전도 Windows 앱에서 등록 원본을 명시적으로 읽어 표시합니다. 기존 자산 소유권/해시·크기/압축 검사와 원본 파서를 재사용하며 현재 악보/Undo·재생·저장 head를 바꾸지 않습니다. 읽는 동안 실제 진행/닫기 취소를 제공하고 취소 종료까지 중복을 차단합니다. 누락/변경된 원본과 원본에 없는 저장 트랙은 오류/표를 유지합니다. 원본 기반 내보내기·직접 적용은 제공하지 않으며 실제 검사 범위는 PHASE-05 최신절을 따릅니다.

## 저장 편집본 읽기 전용 TAB 후속 — 2026-10-26

조회한 NORMALIZED 편집본에서 ‘저장 TAB 보기’를 누르면 독립 악보/lookup을 준비해 기존 ScoreViewport로 TAB만 표시합니다. 저장 트랙 선택은 이 미리보기만 바꾸며 커서·음표 선택/탐색 콜백·재생은 연결하지 않습니다. 닫기·다른 조회 문맥에서는 해제하고 원본/음표 표·현재 편집/저장 head는 유지합니다. 원본 기반 버전은 제외하며 기존 단성6줄/용량·의미 왕복 실패는 표를 유지한 오류로 표시합니다. 준비에 기존 동기 파서를 사용하므로 준비 자체의 즉시 취소·무지연을 보장하지 않습니다. 결과/실제 브라우저·Windows 수용은 PHASE-05 최신절을 따릅니다.

## 조회한 편집본을 새 파일로 보존 — 2026-10-26

저장 이력에서 실제 내용을 조회한 NORMALIZED 편집본의 전체 트랙을 새 JSON/MusicXML로 내보냅니다. 목록의 선택값을 바꿔도 ‘저장 내용 조회’를 다시 누르기 전에는 화면에 표시된 조회 버전이 출력 대상입니다. 원본 GP/MusicXML에 의존하는 버전은 이 출력 대상에서 제외합니다. 현재 편집/Undo·재생과 저장 head/이전 버전·원본 asset은 그대로이며 이전 버전을 자동 적용하지 않습니다. JSON 악보 문서만 포함하고 음원/녹음/프로젝트 전체 복원은 포함하지 않습니다. 기존 검증·비덮어쓰기/앱 데이터 목적지 거부·취소 정책과 단성 편집/8MiB 한도를 재사용하며 결과는 PHASE-05 최신절을 따릅니다.

## 선택 트랙 표시 복사본 — 2026-10-26

현재 표시용 alphaTab 복사본은 선택 트랙 하나만 깊게 복사하며 렌더 인덱스0을 사용합니다. 원래 선택 트랙 인덱스와 음표/박자 객체·도메인/lookup·원본/저장 내용은 유지합니다. 트랙별 표기 설정3종은 복사본의0으로 재매핑합니다. 후속 직렬화 입력도 선택 트랙/전역 메타데이터의 읽기 전용 임시Score로 줄였으며 finish/addTrack이나 부모 변경을 수행하지 않습니다. 최초 원본 파싱 비용은 별도로 남습니다. 실제SVG·JS heap 관측과 테스트/최종검사 상태는 PHASE-08 최신 절을 따릅니다.

## 저장 악보 버전 조회 — 2026-10-26

프로젝트 저장 영역에서 명시적으로 버전 목록과 저장 내용을 조회합니다. 목록은 최신순 100개씩 읽고 선택 버전의 제목·트랙·음표 표를 최대100음 표시합니다. 원본 파일을 다시 읽거나 현재 편집본/Undo·재생·head를 바꾸지 않습니다. NORMALIZED 편집본의 새 파일 출력/읽기 전용 TAB는 위 후속을 따르고, 원본 기반 버전 TAB·재생·적용/삭제·자동 복원은 제공하지 않습니다. 기존 저장 JSON의 소유권·8MiB·SHA·스키마 검증을 재사용하고 실패/취소 시 이전 조회를 유지합니다. 결과와 미실행 범위는 PHASE-05 최신 절을 따릅니다.

## 대형 악보 MusicXML 예산 — 2026-10-25

128트랙/256마디·전체2000음 제한과 출력8MiB 제한은 별도입니다. 큰 박자에서는 쉼표 표기가 늘어나므로 모든 조합의 렌더를 보장하지 않습니다. 정규화 serializer는 헤더/part-list와 각 마디·끝 태그의 실제UTF-8 바이트를 누적해 초과 조각을 게시하거나 전체문자열을 합치기 전에 SCORE_XML_LIMIT로 중단합니다. 이전문서/history·원본은 유지하고 편집/출력 양쪽에서 트랙/마디 축소를 안내합니다. 유효한 출력의 순서/바이트와 새로운 형식·IPC/DB 변경은 없습니다. 회귀/실측과 화면SVG·새Windows 미실행 범위는 PHASE-08 최신 절을 따릅니다.

수동 편집 패널의 기존 Ctrl/Meta+Z·Shift+Z를 유지하고 Windows Ctrl+Y 다시 실행을 같은 history에 연결합니다. 편집 시작 전·녹음/파일/출력 잠금·이미 처리된 이벤트/IME·키 반복/Alt 조합은 무시합니다. 표준 입력과 role=textbox·상속 contenteditable/SVG 자식은 기존 공통 입력 판별기를 사용해 입력 자체의 Undo를 보존합니다. 앱 전역/별도 TAB 영역으로 단축키 범위를 넓히지 않으며 렌더·저장/최대100개 history·원본은 기존 경로를 사용합니다. 구현/검사 결과는 PHASE-05 최신 절을 따릅니다.

## 직접 파일 drop과 기존 가져오기 공유 — 2026-10-25

프로젝트 없는 작업 공간의 File 한 개는 기존 GP/MusicXML/JSON 읽기·정규화/압축 크기/취소·불변 원본 보존을 공유합니다. 악보8MiB·음원256MiB 메타데이터 검증도 파일 선택과 공유하고 내용 읽기/파싱은 서비스가 담당합니다. 미저장 확인 취소/실패·처리 중 중복·최신 잠금/문맥 변화가 현재 편집을 바꾸지 않아야 합니다. 폴더/다중/URL·프로젝트 자산 관리 우회는 지원하지 않으며 상세 계약/검사는 docs/12와 progress/PHASE-02를 따릅니다.

## 장식 표기의 편집 소실 방지 — 2026-10-24

명시적 grace 꾸밈음도 기존 미지원 보호에 포함합니다. on-beat와 마디 안 before-beat의 원래 시각/원본을 유지하며 지원하는 일반 길이로 바꾸지 않습니다. 첫 마디 전의 음수 시작 tick은 기존 도메인에서 거부하는 제약을 유지하며 이를 지원한다고 표시하지 않습니다.

## 음표 선택의 로컬 재생 위치 이동 — 2026-10-24

편집 시작 후 TAB 클릭·목록·이전/다음·좌우/Home/End 선택은 현재 syncAnchors로 선택한 음표 startTick을 ms로 변환해 반주를 일시정지하고 해당 위치로 이동합니다. 배속으로 원곡 시간을 다시 나누지 않습니다. 자동 재생·REC는 시작하지 않으며 전역5초 탐색은 중복 실행하지 않습니다. 음원 미선택/읽는 중/오류에서는 선택만 가능하고 기존 미디어 상태를 유지합니다. 변환 결과가 음원 밖이거나 앵커가 잘못되면 선택은 유지하되 위치는 이동하지 않고 오류를 안내합니다. 새 음표 추가 선택은 탐색하지 않으며 반복/배속·문서/history를 변경하지 않습니다. 앞선 위치 유지 수동 검사는 이전 동작의 이력으로 보존합니다.

## 편집본 트랙 표시 순서 후속 — 2026-10-23

카피 편집 시작 후 선택 트랙을 위/아래로 한 칸 이동합니다. 정렬 로직은 scoreStructure에 두고 UI는 명령/끝 위치·잠금 표시만 담당합니다. tracks 배열이 표시 순서이며 같은 트랙 ID·음표·역할/튜닝·시간/싱크를 유지합니다. 렌더 왕복 검증 후 반영하고 선택은 같은 ID를 따라갑니다. Undo/Redo·새 revision/JSON·MusicXML 경로를 재사용하며 원본 비교 목록/선택과 녹음/믹스 순서는 바꾸지 않습니다. 구현/실제 검증 상태는 PHASE-05 최신 절을 따릅니다.

## 편집본 트랙 삭제 후속 — 2026-10-23

선택 트랙과 그 음표를 명시적 확인 후 현재 편집본에서 제거하고 같은 ID의 Undo/Redo로 복구합니다. 마지막 트랙/잘못된 ID·확인 없음과 녹음/파일 작업 잠금은 차단합니다. 다른 트랙/음표·시간/싱크와 최초 원본·이전 저장 revision·테이크/음원은 유지합니다. 원본 비교는 삭제로 인덱스가 달라지는 문제를 피하도록 별도의 원본 트랙 선택기를 사용합니다. 전체 실제 수용/미실행 범위는 PHASE-05 최신 절을 따릅니다.

## 마디 반복 선택 후속 — 2026-10-23

주 악보의 시작/끝 마디를 펼친 재생 순서로 선택합니다. 같은 마디가 반복되면 원래 번호와 재생 순서를 함께 표시하고 끝 마디 전체/쉼표 마디도 포함합니다. 최신 syncAnchors로 실제 시작/끝 tick을 로컬 음원 ms로 변환하며 음원 밖/250ms 미만/역전 선택은 기존 반복·위치를 유지하고 거부합니다. 정상 적용은 정지·새 epoch·시작 위치 이동까지만 하고 재생은 사용자가 누릅니다. 하단 ms 반복과 같은 엔진 상태이며 녹음/파일 작업 중 잠깁니다. 적용 이후 싱크 변경 시 마디에 자동 재고정하지 않으므로 다시 선택 적용해야 합니다. 구현/미실행은 PHASE-02 최신 절을 따릅니다.

## 악보 표시 선택 후속 — 2026-10-23

## 단일 악보 데이터 모델

- `ScoreDocument`: 프로젝트 ID, 버전, 제목, PPQ(ticks per quarter), tempo map, time signature map, 트랙, sync anchors.
- `Track`: id, 이름(Lead Guitar/Rhythm 등), 악기/튜닝/카포/최대 프렛, display order, note events.
- `NoteEvent`: id, trackId, measureIndex, startTick, durationTicks, pitchMidi, stringIndex(선택), fret(선택), velocity, articulation[], confidence(선택), source(`manual|import|ai`).
- `TempoPoint`: tick, bpm(양수). `TimeSignature`: tick, numerator, denominator.
- `SyncAnchor`: scoreTick, audioTimeMs. 시간·tick은 반드시 단조 증가(비정상 데이터 거부).
- 단음/동시 타격 노트들은 같은 `startTick`을 가질 수 있습니다. 쉼표는 비어 있는 구간으로 취급하거나 명시적 이벤트를 둘 수 있습니다.

## 기초 피치·운지 규칙

표준 기타 6줄, string 1은 가장 얇은 E현. MIDI 음정은 다음과 같습니다.

| 줄 | 개방현 | MIDI |
|---|---|---:|
| 1 | E4 | 64 |
| 2 | B3 | 59 |
| 3 | G3 | 55 |
| 4 | D3 | 50 |
| 5 | A2 | 45 |
| 6 | E2 | 40 |

`pitchMidi = openStringMidi + fret` (표준 프렛 악기, 밴딩/변칙 튜닝 등 제외). 바뀐 튜닝은 각 줄의 개방현 MIDI 값을 바꿉니다. 카포는 기타 표기/실제 소리의 관계가 변경되므로 모델에 따로 저장합니다.

- 동일 음정이 여러 줄/프렛 조합을 가질 수 있음. AI는 문자열/프렛을 **정답이 아닌 후보**로 제공합니다.
- 후보 비용 함수(초안): 손 위치 이동 거리 + 스트링 이동 + 불가능한 손 벌림 페널티 + 개방현 선호도 + 음색/연속성. 연속 노트를 함께 최적화합니다.
- `stringIndex`가 없고 pitch만 있으면 UI에 '운지 미정' 표시, 가능한 후보를 선택하도록 함.

## 악보 import/export

- alphaTab은 GP3~GP 계열, MusicXML importer/renderer로 채택. 실제 지원 형식/버전은 설치 확인.
- import 즉시 **원본 별도 보관 + normalize**. 기존 벤딩/주법/반복 표시 등에서 손실 가능성을 사용자에게 고지.
- 첫 단계 export는 **앱 내부 JSON + MusicXML** 우선. Guitar Pro **쓰기가 자동으로 지원된다고 가정하지 않음**; 가능 여부 검증 후 지원 범위 명시.
- alphaTab adapter는 도메인 `ScoreDocument`와 alphaTab 모델 사이를 변환하며, 모든 import/export에 round-trip fixture를 보유합니다.

## 음원과 악보 싱크

- 파일의 오디오 길이, 인트로, 리타르단도/라이브 템포 때문에 단순 `BPM`만으로 맞지 않을 수 있습니다.
- 사용자 싱크 앵커 예: `(scoreTick=0, audioTimeMs=1600)`과 `(scoreTick=3840, audioTimeMs=5900)`.
- 앵커 사이 구간은 선형 보간하는 MVP 전략(나중에 템포 추정 확대). 영역 바깥은 인접 구간 기울기 연장 또는 안전한 기본 정책을 명시.
- `scoreTickToAudioTime` / `audioTimeToScoreTick` 두 함수는 monotonic·round-trip tolerance를 갖습니다.
- 악보의 템포 맵이 변하면 싱크 앵커 검증 및 사용자에게 재확인 메시지.
- 루프 A/B 지점은 미디어 milliseconds나 score ticks 중 하나로 지정, 프로젝트 저장 시 두 표현을 혼용하지 않습니다. 권장 canonical은 score tick, 재생 직전에 audio ms로 변환.

## 실시간 표시

- Transport engine이 발표한 `playheadAudioMs`를 통해 악보 tick을 결정합니다.
- look-ahead(다음 노트 표시)는 user-configurable 1~2초 범위, 리듬게임 오브젝트가 아닌 TAB 하이라이트 우선.

## 압축 컨테이너 전개량 보호 후속 — 2026-10-22

원본8MiB는 유지하고 ZIP/GPX 해제량·내부 파일 합계32MiB·항목512개를 공통 어댑터에서 검사합니다. 선언 크기만 믿지 않으며 ZIP은 작은 청크의 실제 합계, GPX는 bitstream/BCFS 파일·sector 참조/진행·완료를 확인합니다. 검증한 항목을 내부 비압축 ZIP으로 전달하지만 원본 바이트/프로젝트 자산은 그대로 보존합니다. 한도/형식 오류·읽기 직후 취소는 기존 악보를 유지합니다. 표준 GP7·자체 BCFS/BCFZ·압축 MusicXML 회귀는 확인했고 실제 사용자 GPX의 모든 변형/전체 파서 리소스·CRC/진위를 보장하지 않습니다. 새 확장자나 GP 쓰기 UI를 추가한 것은 아닙니다.
