# 00. 범위·가정·핵심 의사결정

## 2026-10-23 기본 TAB와 별도 오선보 버튼

사용자가 기본은 TAB만 보고 음표는 다른 버튼으로 보고 싶다고 요청했습니다. 주 악보는 TAB로 시작하고 ‘오선보 보기’/‘TAB 보기’ 버튼으로 한 표기씩 전환합니다. F-02의 TAB+오선보 동시 표시보다 이 후속 사용자 결정을 우선하며 동시 표시 후보는 실행본에 적용하지 않습니다. 문서·음표/선택 ID·재생·채점/녹음·저장 데이터는 그대로 두고 표시 상태와 렌더 복사본만 바꿉니다. 최소 기능 UI·공통 스타일을 사용하며 전면 리디자인은 후속입니다.

## 2026-10-22 자동 저장 선택의 로컬 복원

사용자가 켠 프로젝트별 자동 저장 선택을 다음 실행에도 복원하는 후속을 진행합니다. 이전 실행 한정 정책은 이 후속에서만 확장하며 첫 수동 저장 이후/정지/녹음 잠금 등 저장 보호는 유지합니다. 악보/기록은 기존 SQLite·불변 파일을 유지하고, UUID와 선택뿐인 비필수 편의 설정은 화면과 분리한 버전 있는 WebView Storage 어댑터에 보존합니다. 별도 파일 명령/DB 마이그레이션은 추가하지 않습니다. 손상/미지원 설정은 켜지 않으며 원문을 보존하고, 이 편의 선택은 기존 프로젝트 백업 범위에 넣지 않습니다. 자동 저장 내용/강제 종료 복구 기능을 새로 구현한 것으로 확대하지 않습니다. 수용 전에는 완료로 표시하지 않습니다.

## 2026-10-22 독립적인 직접 작성 경로 보완

Phase6B 특화 모델 권리·실제 고급 주법 참조와 별도Windows 검사는 미완료로 유지합니다. 이 외부 조건 때문에 독립적인 개발 전체를 중단하지 않으며, F-06에 정의된 ‘새 악보부터 작성’의 빈 악보 진입 경로를 Phase5 후속/Phase8 기능 회귀 범위로 보완합니다. 이미 완료한 기본 편집기를 재작성하거나 순서를 재설정하지 않습니다. 빈1마디를 기존 편집/출력/프로젝트 저장 구조에 연결하고 고급 판정·모델/DB 버전은 변경하지 않습니다. 실제 수용 전 완료를 선기록하지 않습니다.

## 2026-10-20 고급 판정의 모델 의존성 보류

후속 정정: 무음 차이는 정규화 중간값에서 수치 반올림 증폭으로 좁혔고, 입력 보호 계약과 기존MSRV 호환 후보 검증을 통과했습니다. 원시 출력 비교 실패는 이력으로 유지하되 전체 개발 중단 이유로 사용하지 않습니다. 실제 신호의 오검출/누락 해결과 고급 점수 채택은 별도이며 사후 단음 진단/실제 전기기타 검증 등 진행 가능한 작업을 계속합니다. 자세한 현재 상태는 PHASE-07/진행README를 따릅니다.

기존 검증 ONNX의 Rust 실행 실험에서 tract-onnx0.23.8의 합성 비무음4개/각3출력은 기존 ONNX Runtime과 일치했지만 완전 무음에서는 최대0.208934 차이가 났습니다. 최적화 유무 모두 재현돼 근본 원인은 미규명입니다. 별도400ms 공개28개 조각의 기존 모델도 F1 0.85/참조상 무음3개 모두 추가 후보를 보여 실시간 고급 채점 수용 근거가 부족합니다. 저음량 게이트만으로 해결된다고 가정하지 않습니다. 새 runtime의 제품 의존성/MSRV 변경·고급 점수 적용은 보류하고 기존 앱/단음 판정·로컬 분석은 유지합니다. 중요한 모델/runtime 의존성 문제가 해결되기 전 Phase7을 완료 처리하지 않습니다. 세부 결과·후속 조건은 progress/PHASE-07을 따릅니다.

## 제품 원칙

- **가칭**: GuitarLab. 공개 제품명은 추후 변경 가능합니다.
- **대상**: Windows 10/11 PC의 일렉/어쿠스틱 기타 연습자, 취미 카피 사용자.
- **형태**: 별도 서버 없이 작동하는 로컬 데스크톱 앱. 음원/분석/악보/기록은 기기 내 저장.
- **기능 비전**: 음원 import → 기타 stem 분리 → MIDI 노트 추출 → TAB 운지 후보 생성 → 사용자 편집 → 원곡과 악보 동기화 → 실제 연주 판정 및 점수 저장.
- **두 가지 카피 경로**: (A) AI 자동 카피 후 교정, (B) 원곡을 들으며 처음부터 수동 편집. 언제든 경로 전환 가능.

## 확정 요구사항

1. TAB(및 선택적 오선보) 실시간 진행 커서와 현재 눌러야 할 음/프렛 표시.
2. MP3/WAV 등 음원 로드, Guitar Pro·MusicXML 악보 import; 가능한 형식의 export.
3. 재생 속도 변경(음정 유지), 구간 반복(A-B), 카운트인, 메트로놈, 트랙 볼륨.
4. AI 기타 stem 추출 및 기타 제거 반주, AI 음정/음표 추정, 편집 가능한 TAB 초안.
5. 마이크/오디오 인터페이스 입력 선택 및 튜너/지연 보정.
6. 실시간 판정 `COOL`, `GOOD`, `MISS`, 세부 표시 `EARLY`, `LATE`, `WRONG NOTE`.
7. 점수·콤보·정확도·최고 기록·구간별 오류 확인 및 로컬 저장.
8. 직접 TAB 작성/수정, Undo/Redo, 저장, 가져오기/내보내기.

## 단계별 범위 구분

- **MVP 필수**: 수동 또는 외부 악보 import, 원곡/메트로놈 재생, 커서, 속도/반복, 단음 연주 판정 및 스코어, 설정 저장.
- **정식 1차 목표**: 직접 편집, 기타 분리·자동 카피, 운지 후보, 결과 검토/교정, 연습 기록.
- **고급 목표**: 다성 코드, 벤딩·슬라이드·해머링·풀링, 고급 타브 주법 판정, 분석 자동 정렬 정밀화.

> 모든 요구는 최종 제품 범위에서 유지합니다. 단, 해당 Phase가 아닌 기능은 **명확히 비활성화**하고 UI에 출시 예정으로 표시합니다.

## 측정 가능한 목표(초안, 약속 아님)

- UI 커서: 재생 중 화면의 업데이트는 가급적 60fps 수준; 버벅임을 계측.
- 판정: 음정/온셋 인식 지연을 계측하고 보정 가능한 상태 구현. 시스템/마이크/모델에 따른 편차를 리포트.
- 오디오 드롭: 정상 사용 시 무손실을 목표로, dropped frame 계측.
- 테스트: synthetic fixture 및 라이선스 문제 없는 짧은 악기 샘플에서 판정 재현성 확보.
- 오프라인 동작: 모델이 다운로드된 이후 핵심 기능은 인터넷 없이 사용 가능.

## 명시적인 한계

- 오디오만으로 정확한 물리적 줄·프렛을 단정할 수 없습니다. 지판은 **악보의 권장 운지**이며, 판정은 음높이/리듬이 기본입니다.
- AI 악보 자동 변환은 화음/왜곡/복잡한 주법 및 혼합 음원에서 오류가 납니다. 사용자 수정 필수 경로 제공.
- 원곡과 악보 간 인트로 및 템포 차이는 자동 또는 수동 sync anchor로 정렬해야 합니다.
- 저지연 판정은 오디오 인터페이스/헤드폰을 권장합니다. 마이크 입력은 소음·스피커 누음 때문에 오검출 가능.

### 기능 우선·향후 UI 교체 결정 — 2026-10-15

사용자 요청으로 현재 화면을 완성형 디자인으로 보지 않습니다. 입력 감지·판정·악보 처리·AI 분석·녹음/저장 등의 핵심 기능은 UI 컴포넌트와 분리하고, 화면 교체 시 도메인 모델·IPC·저장 형식을 유지할 수 있도록 설계합니다. 색상·폰트·간격은 공통 토큰을 사용하고 재사용 UI는 필요한 범위에서만 구성합니다. 기능 구현·오류 처리·상태 표시·조작 접근성에 필요한 최소 UI를 제공하며 시각적 다듬기는 후속 리디자인으로 남깁니다.

기존 docs/02의 기능·상태·접근성 요구와 로드맵/테스트 수용 조건은 삭제하지 않습니다. 현재 기능에 필요한 요구를 유지하는 의미로 적용하며 디자인 완성을 별도 선행 조건으로 삼지 않습니다. 기존 정상 기능이나 전체 UI를 지금 일괄 재작성하지 않고, 후속 기능 추가·수정에서 서비스와 UI의 경계를 유지합니다.

## 2026-10-21 열린 새 프로젝트도 직접 보관

첫 보관 후보는 현재 열린 프로젝트 버튼을 막아 다른 프로젝트를 먼저 열도록 했으나, 사용자가 새로 만든 프로젝트를 보관할 수 없다고 반복 보고했습니다. 이 제한은 제품 필수 조건이 아니므로 제거합니다. 미저장 편집 확인 후 현재 프로젝트도 보관하고, native 성공이 확정된 뒤에만 작업 공간을 비웁니다. 취소/실패·실행 중 연습/녹음 거부는 문맥을 보존하며 다른 프로젝트 보관은 현재 편집을 건드리지 않습니다. 파일/원본 삭제·복원 자동 열기는 추가하지 않습니다.

## 2026-10-21 내장 자산 fetch의 자체 origin 허용

실제 Windows 첫 자체 악보 불러오기 실패 후 주 창 connect-src에서 'self'가 누락된 것을 확인했습니다. 명시적 connect-src는 default-src 'self'와 별개로 fetch를 제한하므로 기존 IPC 주소와 자체 origin만 허용하도록 수정합니다. 외부 https/http origin·wildcard/임의 파일 경로를 추가하거나 전체 보안 정책을 끄지 않습니다. 별도 YouTube bridge의 connect-src 'none'과 원격 command 거부는 유지합니다. 수정 전 정책 회귀1개 실패/내장5개·실제 XML bytes 일치 성공을 확인했고 수정 후 전체 회귀/실제 첫 불러오기를 재검증합니다. 근거: [MDN connect-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src), [Tauri CSP](https://v2.tauri.app/security/csp/).
