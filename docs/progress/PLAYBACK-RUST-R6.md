## 결론

- **PASS(자동)**:
  - 준비: `layer_source`가 TAKE·RENDER의 녹음 배속을 돌려주고, 네이티브 준비는 그 값을 보이스(`BusVoice.recorded_rate`)에 붙입니다. WAV 내보내기는 들리는 배속 녹음 레이어를 그대로 `MIX_RATE_UNSUPPORTED`로 거부합니다. 곡 시각 길이 = 프레임 × 녹음 배속.
  - 작업 스레드(`stretch_feed.rs`): 레인 = 1배속 녹음 묶음 하나 + 배속 녹음 보이스마다 하나. 각 레인을 비율 = 재생 배속 / 녹음 배속으로 늘여 더하고, 비율 1이면 늘이지 않습니다. 레인 입력 k = 곡 `start + k × 녹음 배속`이라 구간 되감기도 레인마다 같은 규칙입니다. 늘이기 인스턴스는 재사용합니다. 같은 세대에 배속 녹음 구성이 바뀌면 지금 위치에서 레인을 다시 만듭니다.
  - 버스: 배속 녹음 보이스가 있으면 1배속에서도 조각 경로로 재생하고(`fed()`), 보이스 구성이 바뀌어 경로가 바뀌면 지금 위치에서 새 세대로 이어 갑니다. 1배속 직접 경로의 섞기는 배속 녹음 보이스를 건너뜁니다. 녹음 배속 0.5~1.5 밖은 거부합니다.
  - 화면: 준비 대체 이유 "배속 녹음 테이크"를 없앴습니다. 믹스 패널 안내는 R4 뒤 낡은 "MP3 출력 미지원" 문구를 "WAV·MP3 반주, 배속 녹음 테이크 출력은 미지원"으로 고쳤습니다.
  - 회귀 검사:
    - 녹음 0.5·1.25·1.5배 × 재생 0.5·0.75·1·1.25·1.5배의 클릭 위치가 1.5ms 안. 단 비율 3은 5ms 안(아래 위험).
    - 녹음 배속 그대로 재생하면 원본 샘플 × 음량과 같음(1e-6).
    - 1배속 녹음과 배속 녹음 클릭이 함께 맞음.
    - 구간 반복에서 다음 회차 클릭과 회차 수.
    - 1배속에서 경로가 바뀌어도 위치가 이어짐, 범위 밖 녹음 배속 거부.
    - 네이티브 준비가 녹음 배속을 넘김.
- **큰 입력 성능**: 레이어 12개 중 3개가 0.75배 녹음이라 늘이기 4개를 sleep 없이 돌리면, debug(검증앱)가 실시간의 10.9~14.7배, release가 15.9~21.4배입니다(`stretch_feed_keeps_up_with_many_layers`).
- **검사**: `pnpm verify:app`의 모든 단계 통과(프론트 904·Rust 347), `cargo clippy --locked --all-targets --all-features -- -D warnings` 통과.
- **후속 점검(같은 날)**:
  - CI와 같은 MSRV 검사 `cargo +1.90.0 check --locked --all-targets --all-features` 통과(symphonia·cc·C++ 빌드 포함).
  - 검증앱(debug, R4~R6 포함)을 새로 빌드했습니다. 화면 8개를 돌아도 콘솔 오류·경고가 없었고, 8개 화면 전환을 15번 반복해도 JS 힙이 6.8→7.1MB, DOM이 144개로 그대로라 누수 징후는 없습니다.
  - `docs/12` 네이티브 재생 v1의 "배속 거부" 문구를 R6에 맞췄습니다.
- **NOT RUN(사람 확인)**: 배속 녹음 테이크의 음질·박 맞음 → `MANUAL-CHECKS.md` 33번. 실제 장치 재생은 R5의 무음 검사로 갈음했습니다(이번 변경은 장치 쪽을 바꾸지 않음).

## 위험·후속

- 늘이기 비율이 3에 가까울 때(0.5배로 녹음한 것을 1.5배로 재생)만 클릭이 약 4.3ms 일찍 나옵니다. Signalsmith의 깨끗한 늘이기 범위(`maxCleanStretch = 2`)를 넘는 영역이고, 2.75배까지는 1.1ms 안입니다. 거슬리면 두 단계로 늘이는 방법을 검토합니다.
- 배속 녹음 테이크가 있으면 1배속에서도 음량·mute 변경이 약 85ms 늦게 들리고, 이동 직후 수 ms 무음이 있습니다(R5 배속과 같음).
- 배속 녹음 레이어마다 늘이기 하나씩이라 CPU가 그 수에 비례합니다.
