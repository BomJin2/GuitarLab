# 로컬 데이터와 다운로드 캐시 관리

2026-10-21 기준입니다. 실제 구현·검증 결과는 [Phase 8 기록](progress/PHASE-08.md)을 따릅니다.

## 앱이 저장하는 데이터

프로젝트·악보·연습 기록·관리용 복사 음원·사용자가 REC한 기타 녹음과 보정값은 앱 데이터에 저장합니다. 시스템 출력이나 YouTube 소리를 녹음 파일에 합쳐 저장하지 않습니다. 로컬 진단은 초기화·종료·panic의 고정 코드와 시각만 최근 64건 보존합니다. 경로·오디오·예외 원문을 진단에 넣거나 자동 전송하지 않습니다.

보존할 자료는 [로컬 백업](19-BACKUP-AND-RECOVERY.md)으로 복사할 수 있습니다. 프로젝트 목록의 보관·복원은 아래 Windows 검증 후보에 구현했습니다. 프로젝트/녹음의 영구 삭제·실제 AppData 교체는 아직 없습니다. 캐시 정리를 개인 녹음 삭제 기능으로 간주하지 않습니다.

## 프로젝트 보관과 복원 — Windows 검증 후보

라이브러리의 ‘휴지통에 보관’은 목록에서 숨기는 기능입니다. 프로젝트 행·악보·관리용 복사 음원·녹음·연습 기록과 외부 원본을 지우거나 이동하지 않으며 디스크 공간을 회수하지 않습니다. 자동 보관이나 휴지통 비우기는 없습니다. 실제 사용자 조작 수용 결과는 진행 문서를 따릅니다.

1. 유지할 악보 편집은 프로젝트에 저장합니다. 현재 열린 프로젝트도 보관할 수 있으며 미저장 편집이 있으면 확인합니다. 이 후속 수정의 새 프로젝트 직접 보관·복원은 Windows 사용자 확인을 마쳤습니다.
2. 보관할 프로젝트의 ‘휴지통에 보관’을 누릅니다. 연습·녹음·다른 저장 작업이 진행 중이면 먼저 끝냅니다.
3. ‘휴지통 목록 다시 읽기’로 보관된 제목을 확인합니다.
4. ‘복원’을 누르면 일반 프로젝트 목록에 돌아옵니다. 복원은 현재 작업 공간을 바꾸지 않으며 직접 프로젝트를 열 수 있습니다.

현재 열린 프로젝트는 보관 성공 후 작업 공간을 닫습니다. 확인 취소·작업 오류/취소 때는 현재 악보와 프로젝트를 유지합니다. 이전 후보에서 다른 프로젝트를 먼저 열도록 했던 제한은 사용자 피드백으로 제거했으며 native의 활성 연습·녹음 보호는 유지합니다.

최대 1000개를 보관합니다. 오래된 목록의 버전이나 복원 식별자가 달라졌으면 다시 읽어야 합니다. 취소는 실제 작업 종료까지 기다리며, 이미 커밋한 보관·복원은 늦은 취소로 되돌리지 않습니다. 이 후보는 SQLite v9를 사용합니다. v8의 기존 자료는 유지하지만 v9를 만든 뒤에는 구버전 앱이 해당 DB를 열 수 없으므로 전환 전에 백업합니다.

## 악보 편집과 창 닫기

미저장 악보가 있으면 창을 닫을 때 저장 확인을 제공합니다. ‘계속 편집’을 선택해 프로젝트를 저장하거나 ‘저장하지 않고 닫기’를 명시적으로 선택합니다. 처음 불러오기·저장한 상태·편집을 되돌린 상태는 불필요하게 미저장으로 취급하지 않습니다. 저장 revision과 다른 안전 metadata 보완은 저장 필요 상태로 유지합니다.

녹음·모델 설치·진행 중 파일 작업이 있으면 이 확인과 별개로 정상 종료를 차단합니다. 화면이 응답하지 않으면 5초 뒤 닫기를 다시 눌러 미저장 내용 소실 가능성을 확인할 수 있습니다.

새 프로젝트·프로젝트 열기/다시 열기·프로젝트 악보 선택도 미저장 악보를 확인합니다. 확인창의 취소는 기존 편집과 현재 프로젝트를 유지하며, 확인 실패도 교체 허가로 처리하지 않습니다. 확인은 화면 어댑터에 두고 저장·보관 엔진과 분리합니다. 후속 직접 악보 가져오기 후보는 일반 ‘악보 선택’/‘자체 악보 불러오기’에도 같은 확인을 연결했고 첫 Windows 수용에서 확인 없이 편집이 초기화돼 실패했으나, 비동기 응답/메시지 권한 수정 뒤 실제 확인창 취소로 프렛3 유지를 확인했습니다. 확인창의 응답을 기다리며 취소·오류·화면 이탈의 늦은 승인은 편집을 유지해야 합니다. 강제 프로세스 종료/OS 종료, 미저장 믹스 설정/폼 입력까지 보호하거나 자동 저장하는 기능은 아닙니다.

## 다운로드 캐시 정리

환경 설정의 ‘모델 다운로드 캐시 관리’에서 사용할 기능입니다.

1. ‘캐시 정리 모델’에서 Basic Pitch 또는 Demucs를 고릅니다.
2. ‘캐시 현황 조회’를 눌러 파일 수와 크기 합계를 확인합니다. 모델 파일의 내용 무결성이나 분석 품질을 검사하는 기능은 아닙니다.
3. 필요하면 삭제·재다운로드 안내를 확인하고 동의합니다.
4. ‘선택 캐시 정리’를 누릅니다. 조회 뒤 상태가 바뀌었으면 다시 조회해야 합니다.

현재 번들 Python 3.12용으로 받은 고정 캐시 파일만 정리합니다. 설치 환경/활성화 설정과 프로젝트·녹음·원본 미디어·이전 Python 3.10 캐시는 건드리지 않습니다. 이미 설치된 모델을 지우는 버튼도 아닙니다. 다음 새 설치에는 재다운로드가 필요할 수 있으며, 이 정리 작업이 다운로드를 자동 시작하지 않습니다.

표시하는 MiB는 파일 크기의 합계입니다. 실제 디스크 회수량을 측정한 값은 아닙니다. 알 수 없는 파일·폴더나 링크/junction이 있으면 자동 정리를 거부합니다. 캐시의 하위 폴더를 통째로 지우는 방식은 사용하지 않습니다.

## 취소·오류

‘캐시 작업 취소’를 누르면 남은 작업을 중단하고 정리가 끝날 때까지 기다립니다. 이미 지운 캐시는 취소로 복구하지 않으므로 다시 현황을 조회합니다. 오류 뒤에도 일부 파일이 삭제됐을 수 있으며 기존 설치 환경/사용자 자산은 삭제 대상에서 제외합니다.

모델 다운로드/설치·다른 파일 작업 또는 녹음이 진행 중이면 작업을 마친 뒤 정리합니다. 개발 중에도 실제 사용자 캐시는 자동으로 삭제하지 않으며, 삭제 검증은 자체 임시 자료로 수행합니다.
