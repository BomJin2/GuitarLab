# 09. 테스트 전략 / 검증 기준

## 프로젝트 원본 가져오기의 DB 실패 정리 — 2026-10-28

자체 임시 DB에서 INSERT 거부 trigger와 지연 외래 키의 COMMIT 실패를 각각 재현합니다. 관리용 복사/외부 참조 모두 실패 뒤 자산 폴더의 이름·내용, 기존 원본/저장 revision과 새 외부 원본이 동일해야 하며 다른 작업의 .part 파일을 삭제하면 실패합니다. 정상 중복 제거·잘못된 JSON/복사 취소·기존 재연결 검사를 함께 유지합니다. 실제 개인 프로젝트나 디스크 오류를 주입하지 않습니다.

## 편집 폼 갱신 후 실제 초점의 단축키 — 2026-10-28

keyed form의 수정/삭제·제출로 초점 컨트롤이 사라진 직후 document.activeElement에 Ctrl+Z/Y를 보내 이력이 바뀌는지 검사합니다. 편집 영역에 키를 직접 보내는 방식만으로 수용하지 않습니다. 실패한 편집의 입력값/버튼 초점·입력칸 기본 Undo/영역 밖 키를 보존하고 파일 출력 잠금 중에는 선택창 초점을 가로채지 않아야 합니다. 스크롤 이동 없는 복원과 실제 Tauri 재확인은 사용자 수동 수용으로 구분합니다.

## 합성 DSP 지속 처리·프로세스 메모리 관측 — 2026-10-28

`scripts/Observe-SyntheticDetector.ps1 -Seconds 300`으로 제품의 동일 DSP 소스를 포함한 독립 최적화 실행 파일을 만듭니다. 자체 E2/강한 배음·무음·A4 패턴을48kHz/480프레임·10ms 단위로300초 동안 직접 공급하고 출력 개수/유한 값·인덱스 불연속/최대 입력값 계수를 검사합니다. 작업 시간 p50/p95/max와 절대 예약 시각 초과를 기록하되 실제 오디오 drop/왕복 지연으로 해석하지 않습니다. 스크립트가 만든 자식의 Windows working set/private bytes·누적 CPU만1초 단위로 관측하고 원본 DSP/관측 소스 해시가 바뀌면 실패합니다. 검증 폴더에 새 산출물만 만들며 실패/시간 초과 시 생성한 자식만 정리합니다. 1초/잘못된 인자 자체 검사와 실제 PS5.1·300초 관측을 구분하고 실제 CPAL/녹음/모니터·Tauri 전체 RSS·CPU 격리/출시 임계값 검증으로 확대하지 않습니다.

## 악보 새 파일 출력 작업 수명 — 2026-10-28

취소 뒤 같은 문맥의 DISK_SPACE_LOW/EXPORT_IO를 주입하면 실제 오류가 표시돼야 합니다. AbortError는 취소 안내로, 늦은 완료는 이미 저장된 파일 보존 안내로 구분하며 다른 문서의 늦은 오류는 숨기고 실제 종료 후 새 출력을 허용합니다.

현재 편집/저장 버전 출력에서 이탈·문서 A→B→A 뒤 이전 명령, 최신 조작 잠금/실행 가능 여부, 첫 반환의 이전 결과·진행 숨김을 검사합니다. 선택 변경/취소 후 실제 서비스 종료 전 중복을 막고 이전 취소가 새 작업을 중단하지 않아야 합니다. 모의 native RUNNING→CANCELING→CANCELED/COMPLETED/ERROR를 모두 확인하며 취소 요청만으로 서비스가 먼저 끝나면 실패입니다. 실제 ScoreEditor/useScoreEditing 통합에서 원본 기반 편집의 일반 화면 갱신은 취소하지 않고 취소 종료까지 편집/출력 버튼을 잠그는지 확인합니다. 모의 파일 API와 실제 Windows 파일 선택창 수용은 구분합니다.

## 선택 녹음 작업 수명 회귀 — 2026-10-27

내보내기/사후 분석에서 화면 이탈·테이크 A→B→A 복귀 뒤 보관한 명령을 실행해 파일 작업이 시작되지 않는지 검사합니다. SHA/프레임/샘플레이트/READY 상태 변경의 첫 반환에서 이전 결과·오류/진행을 숨기고, 이름/메모·정렬값만 바뀌면 완료 결과를 유지해야 합니다. 분석 시작값/방식 변경 직후 이전 명령 실행·누락 조건 변경·늦은 성공/실패·이전 취소로 새 작업 중단을 막고 서비스 실제 종료까지 중복 잠금을 확인합니다. 합성 메타데이터/모의 서비스 검사와 실제 WAV·청취 수용은 구분합니다.

## 테이크 정보 변경의 재생 보존 — 2026-10-27

이름/메모 변경 후 WAV/악보 읽기 횟수·미디어 객체·재생 상태/위치·epoch가 유지되는지 확인합니다. 정렬 offset만 바꾸면 실제 파일 위치는 유지하고 표시된 악보 시간과 다음 A/B 전환은 새 offset을 사용해야 합니다. 읽는 중 이름 변경은 현재 요청을 취소/중복하지 않아야 하며 내용 SHA 변경·명시적 다시 읽기는 새 읽기를 실행해야 합니다. 실제 PlayerEngine과 합성 WAV/모의 미디어로 검증하고 실제 장치 청취와 구분합니다.

## 녹음 목록·저장·복구의 문맥 — 2026-10-27

프로젝트 변경 첫 반환의 이전 목록/오류·같은 ID 복귀/이탈 뒤 이전 조회·수정/복구·취소·현재 잠금 우회를 검사합니다. 외부/누락 테이크 거부·정보 저장/복구 중복과 이전 작업의 실제 종료 대기·취소 후 실제 오류/완료 복구본 보존·읽기 전용 목록의 논리 취소/재시도를 모의 API로 검증합니다. 실제 IPC 서비스 검사에서는 복구 취소 뒤 terminal snapshot까지 polling하는지 확인합니다. 화면 검사는 A/B·재생 패널 해제와 미완료/취소 조회를 빈 목록으로 오인하지 않는지를 확인하며 개인 WAV/DB를 입력으로 사용하지 않습니다.

## 믹스 조회·저장의 문맥 보호 — 2026-10-27

프로젝트/반주/revision 전환의 첫 반환부터 이전 믹스/목록·준비/REC 참조를 숨기며 같은 ID 복귀·이탈 뒤 이전 조회/저장·수정/취소가 새 작업을 만들지 않는지 검사합니다. 외부 프로젝트의 믹스/테이크 결과 거부·현재 활성 조건 재확인·프로젝트 해제 시 분리 목록 초기화를 포함합니다. 기존 명시적 준비·파일 읽기 취소·음량/mute/solo·REC 중 청취 조절·출력/원본 보존을 모의 API와 실제 순수 PlayerEngine 검사로 회귀 확인하고 실제 GUI/개인 청취와 구분합니다.

## 로컬 백업의 최신 동의·화면 수명 — 2026-10-27

백업/새 폴더 추출에서 동의를 해제하면 이전 함수·같은 이벤트 안에서도 파일 선택을 시작하지 않아야 합니다. 화면 이탈 뒤의 백업/검사/추출은 외부 작업0회로 확인합니다. 현재 동의를 유지한 정상 재시도·동의 없는 읽기 전용 검사·취소 뒤 늦은 진행률 무시/실제 종료 대기를 모의 서비스로 검사합니다. 실제 개인 DB/백업 ZIP을 읽거나 만들지 않으며 기존 native 백업·새 폴더 보존 검증과 구분합니다.

## 모델 관리의 동의·명령 수명 — 2026-10-27

다운로드 동의 해제와 사용 후 재실행·모델 변경/같은 모델 복귀·화면 이탈 뒤 보관된 명령이 새 네트워크/설치/파일 조회·삭제를 시작하지 않는지 모의 서비스로 검사합니다. 캐시 정리의 동의 해제/소비·조회 갱신과 이전 취소/동의 함수 차단을 포함합니다. 현재 문맥의 정상 실행·취소 후 실제 종료 대기·성공/실패 재시도는 기존 패널 검사로 회귀 확인합니다. 실제 모델 다운로드·설치/삭제와 개인 파일을 테스트 입력으로 사용하지 않습니다.

## 사용자 제공 기타의 AI 입력 — 2026-10-27

명시적 목록 조회/선택 전 분석0회·원본/분리 소스 자동 대체 없음·60초 상한·선택 변경의 초안 초기화·프로젝트/잠금의 이전 명령 차단을 검사합니다. 요청의 두 source ID 동시 지정/경로 문자열과 응답의 잘못된 출처를 거부하고 원본 문서/파일·기존 초안 키를 보존해야 합니다. 자체 SQLite/WAV로 외부 프로젝트 ID·취소·입력 SHA 변조·파일 열기 전61초 거부·서로 다른 입력 초안 복원을 확인합니다. 승인 설치 모델이 있는 환경에서는 자체4초 사용자 기타의 실제8음 추론·임시 정리·초안 복원을 별도 실행하며 개인 음원 품질/실제 UI·별도 OS 수용과 구분합니다.

## AI 초안·분리 미리보기의 문맥 변경 — 2026-10-27

음원/프로젝트·악보 문서·선택 트랙·분석 입력 변경의 첫 반환부터 이전 초안·TAB/오류·미리 듣기를 숨기는지 확인합니다. 이전 분석/조회·소스 선택/취소 함수와 같은 ID 재진입·화면 이탈의 함수가 새 작업을 만들거나 취소하지 않아야 합니다. 현재 문맥의 정상 분석/조회/취소·검토 적용/Undo·Redo, 기존 Blob URL 회수/부분 생성 실패 정리·늦은 응답 무시를 함께 검사합니다. 실제 모델 재분석·개인 음원과 자체 fixture 테스트는 구분합니다.

## 결과 조회 선택·취소·재시도 — 2026-10-27

실제 화면의 각 React commit에서 새 시도 요약/프로젝트 선택과 이전 마디 결과가 섞이지 않는지 확인합니다. 목록/판정의 읽는 중·성공한 빈 결과·실패·취소를 구분하고, 취소/실패 후 같은 시도 재시도는 목록 재조회 없이 가능해야 합니다. 이전 조회의 늦은 완료/오류/진행률, A→B→A 전환의 이전 취소·재시도 함수, 화면 이탈·native 비활성화를 검사합니다. 실제 서비스의 순서/분모/페이지 무결성 검사와 기존 최고점·비정상 종료 요약을 유지합니다. 자체 fixture/DOM 테스트를 개인 DB/실제 앱·청취 검증으로 확대하지 않습니다.

## 저장 조회의 프로젝트 문맥 보호 — 2026-10-26

새 projectId에 반환되는 첫 상태부터 이전 목록/악보가 없는지 검사합니다. 보관한 이전 load/read/cancel 함수는 다른 프로젝트·같은 ID 재진입·unmount 후 새 파일 작업이나 새 조회 취소를 만들면 안 됩니다. 현재 취소는 유효해야 하며 기존 오류/취소의 이전 조회 보존과 늦은 응답 차단을 유지합니다. 기존 이력 UI/독립 TAB/출력과 함께 확인하고 자동 반환 상태 관측을 실제 사용자 화면/파일 수용으로 확대하지 않습니다.

## PC 기본 입력 최초 선택 — 2026-10-26

같은 표시 이름/다른 ID·목록 첫 항목과 다른 기본 장치가 올바르게 선택되는지와 시작 버튼 전 캡처0회를 확인합니다. 늦은 목록/이전 실제 snapshot·수동 선택/해제·채널/gate 수정 보존, 기본 표시 없음/중복·구형 목록의 수동 경로, 기본 장치 소실/변경 시 임의 전환 차단을 검사합니다. 기존 장치 계약/입력·모니터 기본 꺼짐/PC 기본 출력을 함께 확인하고 읽기 전용 실제 장치 열거를 캡처·청취/실제 앱 수용과 구분합니다.

## 입력 패널 재진입 설정 보존 — 2026-10-26

입력 중 화면에 재진입→중단→직접 재시작이 같은 장치/채널/gate를 전달하는지 수정 전 실패로 재현합니다. 초기 snapshot이 늦게 도착한 경우/대기 중 장치·게이트 변경/STOPPED·ERROR의 주기 조회, 목록에서 장치가 없어지거나 채널 수가 줄어드는 경우를 확인합니다. 장치 누락·유효하지 않은 채널에서 시작을 차단하고 임의 채널/다른 장치를 자동 선택·캡처하지 않아야 합니다. 기존 자동 목록/PC 기본 출력·모니터 기본 꺼짐/중복 명령 검사를 함께 실행하며 실제 USB/청취와 구분합니다.

## 원본 기반 저장 TAB 확장 — 2026-10-26

UI 수용은 유일한 새 프로젝트 생성→직접 보관→휴지통 복원과 앱 재실행 후 유지로 확인합니다. 현재 열린 프로젝트를 무조건 막지 않으며 미저장 확인 취소/실패·native 오류/취소 때는 프로젝트/악보/미디어가 유지돼야 합니다. 현재 프로젝트는 실제 성공 뒤에만 문맥을 비우고 다른 프로젝트의 보관·복원은 현재 편집을 바꾸지 않아야 합니다. 실제 사용자 파일 삭제로 검사하지 않습니다. 자동 검사와 사용자 수용·실행 파일 버전을 구분해 기록합니다.

직접 fixture 읽기 회귀에서는 public/dist뿐 아니라 네이티브 내장5개 파일 존재와 압축 해제한 실제 XML bytes를 확인합니다. fetch를 mock한 프론트 성공만으로 Windows의 CSP 수용을 완료하지 않습니다. 주 창 자체 origin/기존 IPC만 connect에 허용하고 외부 HTTP/HTTPS·wildcard를 추가하지 않는지, 별도 영상 bridge connect-src 'none'/원격 command 거부를 유지하는지 확인합니다. fixture 읽기 실패는 LOCAL_FIXTURE_READ_FAILED 고정 안내로 구분하고 임의 오류 원문/개인 경로를 노출하지 않습니다. 실제 첫 읽기와 편집 후 재불러오기 취소는 별도 사용자 수용으로 기록합니다.

## Phase7 실제 DI 주법 파일의 관측 계획 — 2026-10-21

공식 Guitar-TECHS14963133/CC BY4.0의 P1·P2 × Bendings·Vibrato 직접 입력 WAV4개만 선택합니다. 전체 ZIP은 받지 않고 고정 이름·크기/압축 크기·HTTP206/ETag/CRC·개별SHA로 보존합니다. 압축 수신 약155MiB/원본 약367MiB, 작업 여유1GiB를 확인합니다. 모델·개인 녹음은 받거나 분석하지 않습니다. 고정 각 파일의1·6·11·…·56초에서1초씩 총48개를 선택하며 결과에 따라 창이나 임계값을 고르지 않습니다. 원본 mono는 그대로, stereo는 두 채널 산술평균으로 별도 mono float32 창을 만들고 gain 정규화는 하지 않습니다. 공식 자료의≤100ms 시각 오차와 기존 MIDI의 연속 pitchwheel 부재 때문에 파일의 주법 이름을 창별 정답으로 취급하지 않습니다. raw 유지/상승/하강/주기 변화·보류, 음량/coverage/관측 변화를 모두 보고하며 정확도·깊이/속도 오차·허위감점률로 해석하지 않습니다. 제품 점수·실시간 경로는 유지합니다. 출처: [공식 데이터](https://zenodo.org/records/14963133).

## Phase7 외부 실제 기타 표본 선택 — 2026-10-20

Guitar-TECHS14963133의 MIDI8개를 전체 CRC 검사 후 확인했으나 연속 pitchwheel 참조가 없어 주기적 변화의 깊이/속도 정답으로 쓰지 않습니다. 큰 DI WAV는 아직 수신하지 않았습니다. 후속 공개 전기기타 평가는 EGSet12의 고정 레코드11406378/CC BY4.0에서 번호 양 끝01·12의 WAV/JAMS4개(15,442,646바이트)를 선택합니다. 분석 결과로 표본을 고르지 않습니다. 파일 전체의 공식 MD5/크기와 로컬 SHA를 확인하고 기존 Basic Pitch와 native 단음/스펙트럼을 오프라인 비교합니다. onset50/120/180ms·음정50cents 조건은 앞선 계획을 유지합니다. 외부 자료/단일 연주자·앰프 마이크2개 표본이며 새 장치·독립성/주법 전체 성공으로 확대하지 않습니다. 실제 시각/연속 곡선 참조의 정밀도는 먼저 확인합니다. 확인 결과 연속 곡선이 아니라 정수 음표 구간이므로 주법 깊이/속도 정답으로 사용하지 않습니다. native 비교는 경계 전후30ms/구간 중 전환을 제외하고 원래264개 전체와 제외 수를 기록합니다. 실 모델 엔진 동등성은 두 파일 시작0/2/4/6초의 고정8개를 동일 polyphase147/320 float32 텐서로 비교하며 절대1e-4/상대1e-3을 유지합니다. 연산 시간은 입력 문맥·실시간 지연과 구분합니다.

## Phase7 공개 onset 대응 사전 조건 — 2026-10-20

같은 고정4개 원본의6줄 note_midi 주석과 보존된 Basic Pitch 전체 파일 note event를 재추론 없이 비교합니다.
