# 15. 연주 모드 (Performance Mode) — 기타 파트 선택·반주·스코어·세션

> 기존 `연습 모드(Practice)`와 별도이며, 개발 우선순위에 따라 단계적으로 활성화합니다.

## 목표/모드 비교

| 항목 | 카피 모드 | 연습 모드 | 연주 모드 |
|---|---|---|---|
| 주목적 | AI/수동 TAB 제작·수정 | 느린 속도/구간 반복·교정 | 전체 곡 공연처럼 연주·녹음·다시 듣기 |
| 반주 | 분석 대상 원곡 | 로컬 음원/메트로놈 | 선택 기타 제외 로컬 반주, 허용 YouTube 임베드 |
| 악보 | 편집 가능 | 표시 + 커서 | 표시 + 커서 + 트랙 선택 |
| 입력 | 선택 | 입력·판정 | 입력·녹음·선택적 실시간 채점 |
| 반복 | 검토용 | A-B loop 기본 | 전체 곡 우선, 필요한 경우 구간 재연주 |
| 결과 | AI 초안/편집 | 음정·타이밍 분석 | 녹음 파일·파트별 테이크·점수·리플레이 |

## 주요 사용자 흐름

1. 프로젝트 열기 → `연주` 탭 → 악보 트랙 목록(`Lead`, `Rhythm`, `Harmony`, 자유 이름)에 따라 **이번에 연주할 목표 트랙 하나** 선택.
2. 반주 소스 선택: (a) 원래부터 분리되어 있는 stem, (b) 승인된 로컬 음원으로 만든 AI 분리/기타 제거 반주, (c) YouTube의 정식 임베드 반주.
3. 믹서에서 원본 기타/리드/리듬/드럼·베이스 등 **실제 존재하는 오디오 stem에만** 페이더를 제공. 악보 트랙만 있다고 오디오 stem이 생기는 건 아님.
4. 입력 장치/헤드폰/모니터링/레이턴시 보정 확인. `마이크/기타 입력 사용`, `녹음 시작`은 분리된 동작이며 녹음 동의 필수.
5. 카운트인 → 반주 재생 → TAB 하이라이트·지판 표시 → 필요 시 COOL/GOOD/MISS 결과 → 녹음된 take 저장.
6. 결과 화면에서 score/정확도와 녹음 타임라인 나란히 표시. 테이크를 재생하고 A/B 비교, 마디별 이동, 파일 내보내기.
7. `다른 기타 파트 녹음`을 선택하면 원래 테이크를 참조로 들으며 새 목표 트랙을 **별도 파일로 overdub**. 이전 take는 항상 보존.

## 트랙·오디오의 구분

- `ScoreTrack`: 악보상의 연주 대상. 사용자/GP 파일의 트랙 레이블. 실제 오디오 분리와 독립.
- `AudioStem`: 재생 가능한 오디오 파일의 실제 채널. `LEAD_GUITAR` 등은 사용자 지정/검토 가능한 태그이지 자동 정답이 아님.
- `RecordedTake`: 사용자 연주에서 캡처된 오디오. `targetScoreTrackId`, `sourceBackingId`, `startSongMs`, `captureOffsetMs`, `scoreRevisionId`, `calibrationSnapshot`를 기록.
- `TrackBinding`: 선택한 악보 트랙 ↔ 사용자 확인한 stem 또는 take의 연결. 악보 트랙이 둘이어도 분리된 오디오가 하나뿐일 수 있으므로 미연결도 허용.
- `AudioRouting`: 각 stem/take의 gain, mute, pan(지원 시), headphone mix, feedback-safe monitoring. input capture 신호와 시스템 출력 신호는 분리.

## 연주 모드 UI (1440×900 기본)

```text
┌─────────────────────────────────────────────────────────────────────┐
│ GuitarLab / Enter Sandman  [카피] [연습] [연주 ●]  USB Input: OK │
├──────────────┬──────────────────────────────────────────────────────┤
│ 연주 트랙    │ [Lead Guitar ▼]      SCORE 085,400  COMBO 128     │
│ Lead ○       │ ───────── TAB / 현재 마디·노트 ────────────────      │
│ Rhythm ●     │ ───────── TAB / NEXT 음표 ─────────────────────      │
│ 트랙 관리    │ ───────── 지판 / 눌러야 할 음 ─────────────────      │
├──────────────┼──────────────────────────────────────────────────────┤
│ 반주 선택    │ [원곡] [기타 뺀 반주] [YouTube 검색]                 │
│ Mixer        │ Drums ▓▓▓▓ Bass ▓▓▓▓ Rhythm ▓▓ Lead [MUTE]        │
├──────────────┴──────────────────────────────────────────────────────┤
│ ▶  00:58 / 04:10  BPM 120   [● REC] [STOP] [녹음 다시 듣기]    │
│ 테이크 01 ▓▓▓▓▓▓▓▓  테이크 02 ────────── [A/B 비교] [내보내기]│
└─────────────────────────────────────────────────────────────────────┘
```

- 연주 트랙 바꾸기: playback 중에는 즉시 판정 대상만 바꾸지 않고 정지/재시작 또는 명시적인 구간 변경 확인.
- 녹음 중: 빨간 `REC` 및 타이머/저장 위치/입력 레벨, 정지·저장/취소. OS 장치 연결 끊김/디스크 용량 부족은 오류 상태 표시.
- 재생 동기화 불확실(YouTube): `영상과 악보의 타이밍 보정이 필요합니다`와 `정밀 점수 비활성` 알림. 점수를 임의로 생성하지 않습니다.
- 리드와 리듬이 겹치는 경우 선택한 악보 트랙에만 score matcher를 연결. 다른 트랙의 음은 점수에서 제외.
- `파트별 악보 보여주기`와 `파트별 음원 제거하기`를 명확히 다른 버튼/기능으로 제공합니다.

## 진입/완료 조건

- 필수: 유효한 score revision, 연주할 score track, 선택한 backing source 또는 무반주 모드.
- `REC` 필수: 정상적인 입력 장치, 파일 쓰기 권한, 공간 확인, 캘리브레이션 정보. 채점 여부와 별개.
- 완료: 자체 녹음의 PCM가 재생 가능하고 프로젝트에 연결, 선택된 악보 트랙/음원 정보와 저장된 scoring result가 일관.
- 녹음 없이 악보를 보며 연주하거나 YouTube를 시청하는 기능도 정상 동작.

## 고장 복구

- 카운트인 실패/오디오 장치 변경/입력 소멸 시 채점 중지, 녹음 청크는 가능한 범위에서 보존하고 미완료 take 상태로 남깁니다.
- YouTube 재생/네트워크 중단 시 세션은 pause/unscored 전환, 백킹 선택 화면으로 복귀. 녹음된 사용자 소리는 삭제하지 않음.
- 모델이 리드·리듬 분리에 실패하면 `기타 전체 제거` 또는 `사용자가 마련한 개별 stem`을 안내.

## 수용 조건

- 선택한 악보 트랙만 판정되고, 트랙 변경 후 이전 judgement가 오염되지 않음.
- Lead -> Rhythm 교체 시 다른 TAB 표시, 동일 곡 내 다른 take 저장 가능.
- 파생 반주를 선택해도 원본 오디오/악보 불변.
- YouTube와 로컬 반주의 기능 제한을 혼동하지 않는 UI 및 자동 테스트.

## 사용자 제공 기타 파일의 연주 연결 후보 — 2026-10-20

저장 IMPORTED_STEM 레이어는 명시적 믹스 준비에서 기존 무결성 검증된 WAV 읽기를 사용하고 하단 로컬 transport의 시간·배속·pause/seek/반복을 따릅니다. gain/mute/solo/수동 offset을 재사용하며 원본/AI STEM/RecordedTake를 구분합니다. 자동 정렬·샘플 정밀 동기는 보장하지 않습니다. REC는 기존 선택 입력만 저장하고 referenceTakeIds에는 실제 TAKE만 넣습니다. 세부 계약/검사·수용 결과는 docs/12와 PHASE-06B를 따릅니다.
